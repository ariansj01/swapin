# Swaapin E2E Tests — مستندات تست‌های End-to-End با Cypress

## معرفی
این مجموعه شامل تست‌های End-to-End برای پلتفرم معاوضه سواَپین (Swapin) است که با استفاده از فریم‌ورک Cypress پیاده‌سازی شده است. هدف از این تست‌ها پوشش تمام جریان‌های کاربری اصلی و فرعی اپلیکیشن به منظور شناسایی باگ‌ها و جلوگیری از رگرسیون پس از هر استقرار می‌باشد.

## پیش‌نیازها
- PHP >= 8.1 با اکستنشن‌های موردنیاز (pdo_mysql, mbstring, gd, curl)
- MySQL/MariaDB (برای اجرای تست‌های وابسته به دیتابیس)
- Node.js >= 18.x
- npm >= 9.x
- مرورگرهای Chrome یا Firefox (برای اجرا به صورت Headed)
- دسترسی سرور محلی XAMPP/WAMP/LAMP با آدرس `http://localhost/swaapin`

## نصب و راه‌اندازی

### گام ۱: نصب وابستگی‌های npm
```bash
cd /path/to/swaapin
npm install
```

### گام ۲: پیکربندی متغیرهای محیطی (اختیاری)
اگر نیاز به جایگزینی مقادیر پیش‌فرض دارید:
```bash
cp cypress.env.example.json cypress.env.json
```
سپس مقادیر `cypress.env.json` را مطابق محیط خود ویرایش کنید.

### گام ۳: اطمینان از در دسترس بودن سرور محلی
اطمینان حاصل کنید که:
- سرور Apache و MySQL XAMPP فعال هستند
- پروژه در آدرس `http://localhost/swaapin` در دسترس است
- دیتابیس پروژه ساخته شده و مایگریشن‌ها اجرا شده‌اند
- (اختیاری) دیتای دمو با `php seed/seed_demo.php` وارد شده باشد

## اجرای تست‌ها

### اجرای تعاملی (Interactive Mode — توصیه‌شده برای توسعه)
```bash
npm run cypress:open
```
پس از باز شدن پنجره Cypress:
1. گزینه **E2E Testing** را انتخاب کنید
2. مرورگر دلخواه (Chrome/Firefox) را انتخاب کنید
3. روی فایل تست دلخواه کلیک کنید تا اجرا شود

### اجرای سرخطی (Headless Mode — برای CI/CD و سرعت بیشتر)
```bash
# اجرای تمام تست‌ها به صورت headless با مرورگر پیش‌فرض Electron
npm run cypress:run

# اجرا با مرورگر Chrome (headless)
npm run cypress:run:chrome

# اجرا با رابط کاربری مرورگر (Headed) برای دیباگ
npm run cypress:run:headed
```

### اجرای یک فایل تست خاص
```bash
# مثال: فقط تست‌های احراز هویت
npx cypress run --spec "cypress/e2e/auth/auth.cy.js"

# مثال: فقط تست‌های دودویی و رگرسیون
npx cypress run --spec "cypress/e2e/smoke/smoke-regression.cy.js"
```

### اجرا برای محیط استیج
```bash
CYPRESS_baseUrl=https://staging.swaapin.ir npx cypress run
```

## دستورات سفارشی Cypress
در فایل `cypress/support/commands.js` دستورات زیر تعریف شده‌اند:

| دستور | توضیحات | نمونه استفاده |
|-------|---------|---------------|
| `loginByPhone(phone, redirect)` | ورود کاربر با شماره تلفن و OTP | `cy.loginByPhone('09999999999', '/dashboard.php')` |
| `loginAsAdmin(email, password)` | ورود ادمین با ایمیل و رمز عبور | `cy.loginAsAdmin('admin@swaapin.ir', 'pass')` |
| `logout()` | خروج کاربر از سیستم | `cy.logout()` |
| `visitAuthenticated(url, phone)` | باز کردن صفحه‌ای که نیاز به احراز هویت دارد | `cy.visitAuthenticated('/listings/create.php')` |
| `checkPageAccess(url, options)` | بررسی دسترسی به صفحه (احراز هویت دار/ندار، محتوای موردانتظار) | `cy.checkPageAccess('/dashboard', { requireAuth: true })` |
| `verifyLink(selector)` | بررسی درستی لینک انتخاب‌شده | `cy.verifyLink('footer a:first')` |

## داده‌های تست (Fixtures)
داده‌های نمونه در پوشه `cypress/fixtures/` قرار دارند:
- `users.json`: اطلاعات کاربران تست (شماره تلفن، نام، شهر و ...)
- `admin.json`: اطلاعات حساب ادمین تست (ایمیل و رمز عبور)
- `listings.json`: اطلاعات آگهی نمونه برای تست ایجاد آگهی

## گزارش‌دهی و دیباگ

### اسکرین‌شات‌ها
در صورت شکست هر تست، به صورت خودکار یک اسکرین‌شات از صفحه در لحظه خطا در پوشه زیر ذخیره می‌شود:
```
cypress/screenshots/<spec-name>/<test-name> (failed).png
```

### ویدیوها
در حالت Headless، ویدیوی کامل اجرای هر تست در پوشه زیر ذخیره می‌گردد:
```
cypress/videos/<spec-name>.mp4
```

### گزارش خطا در کنسول
برای مشاهده لاگ‌های دقیق:
```bash
npm run cypress:run -- --verbose
```

## اجرا در CI/CD

### GitHub Actions
فایل `.github/workflows/e2e-cypress.yml` به صورت خودکار در رویدادهای زیر اجرا می‌شود:
- Push به شاخه‌های `main`, `staging`, `develop`
- Pull Request به سمت همین شاخه‌ها
- اجرای دستی از طریق Actions → Run workflow

مراحل اجرا در CI:
1. راه‌اندازی MySQL 8.0 به صورت سرویس جانبی
2. نصب PHP 8.3 و وابستگی‌های Composer
3. کپی فایل محیط و اجرای مایگریشن‌ها و دیتای دمو
4. استارت سرور PHP در پورت 8080
5. نصب Node.js 20 و وابستگی‌های npm
6. اجرای تست‌ها به صورت موازی در 7 گروه مستقل (بر اساس ماژول‌ها)
7. آپلود اسکرین‌شات‌ها و ویدیوها به صورت Artifact در صورت نیاز
8. در صورت شکست، لاگ سرور PHP نیز آپلود می‌شود

## نکات مهم برای نگهداری
1. **عدم وابستگی بین تست‌ها**: هر تست به صورت مستقل طراحی شده و می‌تواند به صورت انفرادی اجرا شود.
2. **استفاده از Fixtures**: همیشه از داده‌های فیکسچر برای تست استفاده کنید؛ هرگز به داده‌های واقعی تولید تکیه نکنید.
3. **پاکسازی خودکار**: پس از هر تست، Cookies و Local Storage پاکسازی می‌شوند تا تداخل با تست بعدی پیش نیاید.
4. **تحمل خطاهای بی‌اثر**: خطاهای مربوط به `google is not defined` (وقتی GTM در محیط تست بارگذاری نشده) و `ResizeObserver loop` نادیده گرفته می‌شوند تا تست‌ها به درستی اجرا گردند.
5. **تکرار اجرا**: در حالت Headless تست‌های ناموفق یک بار دیگر ری‌ترای می‌شوند (`retries.runMode: 1`) تا خطاهای موقت نتایج را خراب نکنند.
