# پیاده‌سازی کامل Flow «معاوضه کاربر با فروشگاه»

یک Flow کامل و اختصاصی برای **معاوضه کاربر با فروشگاه** در سواپین پیاده‌سازی کن.

یک تصویر مرجع از Journey کامل این Flow در اختیار تو قرار گرفته است.
**تصویر مرجع باید مبنای UI/UX و ترتیب مراحل باشد.**

هدف این است که Flow پیاده‌سازی‌شده از نظر:

* ترتیب مراحل
* ساختار صفحات
* اطلاعات نمایش داده‌شده
* CTAها
* وضعیت‌ها
* مذاکره
* پیشنهاد جدید
* تأیید نهایی

با Flow تصویر مطابقت داشته باشد.

---

## 1. شروع Flow

کاربر وارد صفحه محصول فروشگاه می‌شود.

روی Card محصول باید مشخص باشد که محصول هم برای خرید نقدی و هم معاوضه قابل استفاده است.

Badge:

```text
قابل خرید و معاوضه
```

CTAها:

```text
[ خرید کالا ]
[ ⇄ پیشنهاد معاوضه ]
```

کلیک روی «پیشنهاد معاوضه» نباید کاربر را وارد Flow معاوضه کاربر ↔ کاربر کند.

باید وارد Flow اختصاصی:

```text
User → Store
```

شود.

---

# 2. مرحله اول: انتخاب کالای کاربر

عنوان:

```text
پیشنهاد معاوضه
```

متن:

```text
چه کالایی برای معاوضه پیشنهاد می‌دهید؟
کالای خود را از لیست انتخاب کنید
```

لیست کالاهای متعلق به کاربر نمایش داده شود.(از لبست اگهی هایی که ثبت کرده و اگر کالای ثبت شده ای نداشت ی مودال باز بشه که یک کالا رو پیشنهاد بده یعنی عنوان توضیحات دسته بندی قیمت و عکس رو ثبت و ارسال کنه)

برای هر کالا حداقل:

* تصویر
* عنوان
* دسته‌بندی
* ارزش تقریبی
* امکان انتخاب
* امکان حذف/تغییر انتخاب

نمایش داده شود.

مثال:

```text
گوشی سامسونگ S23
2/256GB

ارزش تقریبی
۶,۰۰۰,۰۰۰ تومان
```

در پایین:

```text
[ انتخاب کالای دیگر ]
```

و:

```text
مبلغ تکمیلی (اختیاری)
```

قرار گیرد.

---

# 3. مبلغ تکمیلی

کاربر می‌تواند مبلغ تکمیلی پیشنهاد خود را وارد کند.

مثال:

```text
ارزش کالای شما:
۸,۰۰۰,۰۰۰ تومان

ارزش محصول فروشگاه:
۱۰,۰۰۰,۰۰۰ تومان

مبلغ تکمیلی:
۲,۰۰۰,۰۰۰ تومان
```

مبلغ تکمیلی باید Validation شود.

مقدار منفی، مقدار نامعتبر یا مقدار خارج از محدودیت‌های منطقی نباید پذیرفته شود.

---

# 4. مرحله بررسی پیشنهاد

قبل از ارسال، صفحه‌ای مشابه تصویر مرجع ایجاد کن:

```text
بررسی پیشنهاد
```

متن:

```text
پیشنهاد شما به فروشگاه
لطفاً جزئیات پیشنهاد خود را قبل از ارسال بررسی کنید.
```

دو Card کنار هم:

### کالای فروشگاه

```text
لپ‌تاپ Lenovo IdeaPad
ارزش تقریبی:
۱۰,۰۰۰,۰۰۰ تومان
```

### کالای شما

```text
گوشی سامسونگ S23
ارزش تقریبی:
۶,۰۰۰,۰۰۰ تومان
```

بین دو Card یک علامت معاوضه نمایش داده شود.

پایین:

```text
مبلغ تکمیلی شما:
۲,۰۰۰,۰۰۰ تومان
```

هشدار:

```text
با ارسال این پیشنهاد، فروشگاه آن را بررسی خواهد کرد.
```

CTA اصلی:

```text
[ ارسال پیشنهاد ]
```

CTA ثانویه:

```text
[ بازگشت و ویرایش ]
```

---

# 5. ارسال پیشنهاد

پس از ارسال موفق، صفحه Success نمایش داده شود.

عنوان:

```text
پیشنهاد شما ارسال شد!
```

متن:

```text
فروشگاه در حال بررسی پیشنهاد شماست.
```

اطلاعات پیشنهاد:

```text
شماره پیشنهاد: #1254
فروشگاه: فروشگاه دیجیتال کالا
زمان ارسال: امروز، ۱۴:۳۵
```

و وضعیت:

```text
در انتظار پاسخ فروشگاه
```

CTA:

```text
[ مشاهده پیشنهاد من ]
```

---

# 7. مذاکره با فروشگاه

هر Offer باید Conversation اختصاصی خودش را داشته باشد.

CTA:

```text
گفت‌وگو درباره معاوضه
```

Chat باید به Offer متصل باشد.

نمونه:

```text
پیشنهاد معاوضه #1254
```

سپس:

```text
شما:
این گوشی سالمه و ۲ میلیون هم مابه‌التفاوت می‌دم.

فروشگاه:
اگر ۳ میلیون مابه‌التفاوت بدی قبول می‌کنیم.

شما:
موافقم.
```

Chat صرفاً یک پیام‌رسان عمومی نباشد.

هر پیام باید در Context همان Offer قرار داشته باشد.

---

# 8. پیشنهاد جدید فروشگاه

فروشگاه باید بتواند Counter Offer ارسال کند.

مثلاً:

```text
پیشنهاد جدید فروشگاه

کالای شما:
Samsung S23

مابه‌التفاوت:
۳,۰۰۰,۰۰۰ تومان
```

کاربر باید بتواند:

```text
[ قبول پیشنهاد ]
[ رد پیشنهاد ]
[ ادامه مذاکره ]
```

را انجام دهد.

---

# 9. وضعیت‌های Offer

Backend باید State Machine مشخص داشته باشد.

حداقل:

```text
pending
negotiating
counter_offered
accepted
rejected
```

در صورت نیاز وضعیت‌های تکمیلی را مطابق معماری فعلی پروژه اضافه کن.

وضعیت UI باید همیشه از Backend خوانده شود.

هیچ وضعیت مهمی نباید فقط در Frontend مدیریت شود.

صفحه:

```text
تأیید نهایی
```

نمایش داده شود.

عنوان:

```text
پیشنهاد معاوضه مورد توافق قرار گرفت
```

اطلاعات:

```text
کالای فروشگاه:
Lenovo IdeaPad

کالای شما:
Samsung S23

مبلغ تکمیلی:
۳,۰۰۰,۰۰۰ تومان
```

```text

```

بعد از تأیید:

```text
🎉 معاوضه تکمیل شد!
```

و اطلاعات معامله نمایش داده شود.

# 11. داشبورد «معاوضه‌های من»

در داشبورد کاربر، پیشنهادهای معاوضه نمایش داده شوند.

برای هر مورد:

* محصول فروشگاه
* کالای پیشنهادی کاربر
* مبلغ تکمیلی
* وضعیت
* تاریخ
* لینک مشاهده جزئیات

Tabها:

```text
همه
در انتظار
تکمیل شده
```

---

# 12. Backend

قبل از ایجاد Code جدید، ساختار فعلی پروژه را بررسی کن.

این بخش‌ها را پیدا کن:

```text
trade_offers
conversations
messages
listings
stores
users
```

اگر سیستم Offer و Chat موجود است، از همان سیستم استفاده و آن را Extend کن.

از ساخت سیستم موازی و Duplicate جلوگیری کن.

Offer باید مشخص کند که مربوط به کدام Flow است:

```text
user_to_user
user_to_store
```

برای User → Store حداقل اطلاعات منطقی:

```text
offer_id
user_id
store_id
store_listing_id
user_listing_id
store_listing_value
user_listing_value
cash_difference
status
conversation_id
created_at
updated_at
```

ساختار دقیق را با Schema فعلی پروژه هماهنگ کن و بدون نیاز Migration غیرضروری ایجاد نکن.

---

# 13. Permission

حتماً بررسی کن:

* فقط صاحب کالا بتواند آن را پیشنهاد دهد.
* کاربر فقط کالاهای خودش را انتخاب کند.
* فقط فروشگاه صاحب Listing بتواند Offer را مشاهده و مدیریت کند.
* کاربر نتواند Offer کاربر دیگر را تغییر دهد.
* پیام‌های Conversation فقط برای افراد مجاز قابل مشاهده باشند.
* پس از نهایی شدن معامله، تغییر Offer محدود شود.

---

# 14. Transaction و Data Integrity

ارسال Offer باید Atomic باشد.

در صورت موفقیت:

```text
Create Offer
+
Create/Attach Conversation
+
Create initial message/event
```

باید با هم موفق شوند.

اگر یکی از مراحل Fail شد، داده ناقص باقی نماند.

# 15. UI/UX

از تصویر مرجع برای طراحی استفاده کن.

موارد زیر باید حفظ شوند:

* Cardهای محصول
* Step Indicator
* نمایش دو کالا در مقابل یکدیگر
* علامت معاوضه
* نمایش مبلغ تکمیلی
* Success State
* Offer Detail
* Chat
* CTAهای اصلی و ثانویه
* وضعیت Offer
* صفحه تأیید نهایی

Responsive بودن الزامی است.

در Mobile Layout باید Cardها و اطلاعات به شکل عمودی و خوانا قرار بگیرند.

---

# 16. نکته بسیار مهم

Flow کاربر ↔ کاربر را خراب نکن.

این Flow باید جدا بماند:

```text
User ↔ User
کالای من
↔
کالای تو
```

و Flow جدید:

```text
User → Store
کالای من
+
مابه‌التفاوت احتمالی
→
کالای فروشگاه
```

باشد.

این دو Flow از نظر UX، Business Logic و State باید قابل تشخیص باشند.

---

# 17. معیار نهایی تست

سناریوی زیر باید کامل اجرا شود:

```text
محصول فروشگاه
↓
پیشنهاد معاوضه
↓
انتخاب کالای کاربر
↓
تعیین مبلغ تکمیلی
↓
بررسی پیشنهاد
↓
ارسال
↓
Success
↓
در انتظار پاسخ فروشگاه
↓
فروشگاه پیشنهاد را مشاهده می‌کند
↓
مذاکره
↓
Counter Offer
↓
قبول Counter Offer
↓
تأیید نهایی
↓
تکمیل فرآیند معاوضه
```

در پایان، Backend، Database، API، Frontend، Chat، Permission و State Management را تست کن.

**صرفاً UI را از روی تصویر کپی نکن؛ کل Business Flow را مطابق تصویر و توضیحات پیاده‌سازی کن.**
